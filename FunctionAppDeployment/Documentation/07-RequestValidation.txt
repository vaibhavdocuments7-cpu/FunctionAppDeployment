================================================================================
7. REQUEST VALIDATION (Input Sanitization)
================================================================================

WHAT: Scans all incoming requests for malicious patterns before they reach
      your function code. Acts as a code-level WAF.
FILE: Middleware/RequestValidationMiddleware.cs
POSITION: Runs after Security Headers, before API Key (2nd in pipeline)

HOW IT WORKS:
  - Regex-based pattern detection on URL, query params, headers, and body
  - Blocks request immediately with 400 Bad Request if malicious pattern found
  - Runs early in pipeline so malicious payloads never reach downstream code

================================================================================
ATTACKS BLOCKED
================================================================================

  ┌─────────────────────┬─────────────────────────────────────────────┐
  │ Attack Type         │ Example Patterns Detected                   │
  ├─────────────────────┼─────────────────────────────────────────────┤
  │ SQL Injection       │ ' OR 1=1, UNION SELECT, DROP TABLE,        │
  │                     │ INSERT INTO, DELETE FROM, EXEC(, xp_       │
  ├─────────────────────┼─────────────────────────────────────────────┤
  │ XSS (Cross-Site     │ <script>, javascript:, onerror=,           │
  │ Scripting)          │ onload=, eval(, document.cookie            │
  ├─────────────────────┼─────────────────────────────────────────────┤
  │ Path Traversal      │ ../, ..\, /etc/passwd, /windows/system32   │
  ├─────────────────────┼─────────────────────────────────────────────┤
  │ Command Injection   │ ; ls, | cat, && rm, $(command),            │
  │                     │ `command`, cmd /c, powershell               │
  ├─────────────────────┼─────────────────────────────────────────────┤
  │ Oversized Payload   │ Request body > 1 MB (configurable)         │
  └─────────────────────┴─────────────────────────────────────────────┘

WHAT IT SCANS:
  1. URL path          → e.g., /api/users/../../../etc/passwd
  2. Query parameters  → e.g., ?search=' OR 1=1--
  3. Request headers   → e.g., X-Custom: <script>alert(1)</script>
  4. Request body      → e.g., POST with {"name": "'; DROP TABLE users--"}

CONFIGURATION (Program.cs):
  builder.Services.Configure<RequestValidationOptions>(options =>
  {
      options.MaxBodySizeBytes = 1_048_576;    // 1MB max body
      options.MaxUrlLength = 2048;
      options.MaxQueryStringLength = 1024;
      options.MaxHeaderValueLength = 8192;
      options.BlockSqlInjection = true;
      options.BlockXss = true;
      options.BlockPathTraversal = true;
      options.BlockCommandInjection = true;
      options.EnforceContentType = true;
      options.ExcludedFunctions = new List<string> { "HealthCheck", "IpCheck" };
  });

RESPONSE WHEN BLOCKED (400):
  {
      "error": "Bad Request",
      "message": "Potential SQL injection detected in query"
  }

================================================================================
HOW TO TEST
================================================================================

  # SQL Injection — should return 400
  GET /api/FunctionDeployment?search=' OR 1=1--

  # XSS — should return 400
  GET /api/FunctionDeployment?name=<script>alert('xss')</script>

  # Path Traversal — should return 400
  GET /api/../../etc/passwd

  # Command Injection — should return 400
  GET /api/FunctionDeployment?cmd=; rm -rf /

  # Normal request — should pass through
  GET /api/FunctionDeployment?search=hello
