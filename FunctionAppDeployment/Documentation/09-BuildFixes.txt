JWT DEBUGGING — ENHANCED ERROR MESSAGES
================================================================================

WHAT: When JWT validation fails with "Invalid audience", the error message
      now shows the ACTUAL audience from the token vs what's configured.

WHY: After recreating Azure App Registration, the Client ID changes.
     Old audience values hardcoded in AllowedAudiences won't match new tokens.
     This enhanced message immediately shows the mismatch.

BEFORE (unhelpful):
  {
    "error": "Unauthorized",
    "message": "Token validation failed: Invalid audience"
  }

AFTER (shows exact mismatch):
  {
    "error": "Unauthorized",
    "message": "Token validation failed: Invalid audience. Token has: [api://NEW-CLIENT-ID], Allowed: [api://OLD-CLIENT-ID, OLD-CLIENT-ID]"
  }

HOW TO FIX AUDIENCE MISMATCH:
  1. Read the error message to see actual vs allowed audiences
  2. Update Program.cs → AllowedAudiences with the correct Client ID
  3. Update local.settings.json → AzureAd__ClientId
  4. Redeploy: func azure functionapp publish <app-name>
